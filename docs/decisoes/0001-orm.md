# 0001 · ORM e migrações: Drizzle

Data: 19/10/2026 · Status: aceita · Issue: #5

## Contexto

Precisamos de migrações versionadas, tipagem forte, SQL cru quando preciso (`pg_trgm`, consultas de métricas), inteiros grandes para centavos e transações. Toda consulta com dado do lojista filtra por `comerciante_id`.

## Opções

| Opção | A favor | Contra |
| --- | --- | --- |
| Drizzle | Schema em TypeScript, SQL explícito, migrações em SQL legível, leve, `sql` template para `pg_trgm` | Ecossistema menor que o do Prisma |
| Prisma | Popular, bom tooling | Cliente gerado, SQL cru menos ergonômico, mais peso no contêiner |
| Kysely | Query builder excelente | Sem schema nem migrações declarativas prontas |
| TypeORM | Integração antiga com Nest | Tipagem fraca e comportamento implícito |

## Decisão

Drizzle (`drizzle-orm` + `drizzle-kit`). O schema fica em `src/infra/database/schema.ts`, as migrações em `drizzle/`, geradas com `npm run db:generate` e aplicadas com `npm run db:migrate` (também na subida do contêiner).

Migração que o Drizzle não gera (extensões, funções) entra com `npx drizzle-kit generate --custom --name=<nome>`.

## Consequências

- Dinheiro em `bigint` com `mode: "number"` ou `integer`, sempre centavos.
- Revisar o SQL gerado em toda PR que mexe no schema.
